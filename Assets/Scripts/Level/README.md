# Уровни: построение локации из .aseprite и путь камеры

Инструменты редактора для сборки уровня:

| Меню | Окно | Зачем |
| --- | --- | --- |
| `Psynetika → Шаблон уровня` | `LevelTemplateWindow` | новая сцена уровня из шаблона (камера, игрок, UI уже на месте) |
| `Psynetika → Построение локации` | `LocationBuilderWindow` | арт и коллизия уровня из одного `.aseprite` со слоями |
| `Psynetika → Путь камеры` | `CameraPathEditor` | линия, по которой ходит камера, коридор для конфайнера, зум по участкам |

## Быстрый старт: новый уровень

1. **Шаблон уровня** → «Имя сцены» → **Создать**. Появится `Assets/Scenes/<имя>.unity` и сразу
   откроется окно «Построение локации». Если шаблона ещё нет, см. [Шаблон уровня](#шаблон-уровня).
2. В «Построении локации» перетащить `.aseprite` уровня в поле **Файл .aseprite**.
   Если окно пишет про Merge Frame, нажать **Переключить на Individual Layers**.
3. Выбрать **Конфиг правил** (`Assets/Resource/Level/LocationBuildConfig.asset`) или создать его кнопкой
   **Создать конфиг по умолчанию**.
4. Проверить таблицу слоёв: у каждого слоя в колонке «Что будет» написана его роль. Жёлтые слои
   не подошли ни под одно правило, им можно назначить роль вручную (см. [Роли слоёв](#роли-слоёв)).
5. **Построить локацию**. Арт и коллайдеры появятся под объектом `Локация (сгенерировано)`.
6. Подогнать **Масштаб карты** под рост персонажа (персонаж около 2.1 юнита).
7. **Создать путь камеры** → провести линию в Scene View → **Построить коридор**.

Всё созданное утилитой живёт под одним корнем с `LocationBuildMarker`. Ручные объекты сцены
утилита не трогает никогда, «Перестроить» пересоздаёт только детей этого корня.

## Подготовка файла .aseprite

* **Импорт — Individual Layers.** В режиме Merge Frame импортёр склеивает все слои в один спрайт,
  и разбирать нечего. Окно предлагает переключить режим само.
* **Раскладка слоёв — Pivot Space = Canvas** (так ожидает `SpriteMask2D`): у всех слоёв
  `localPosition = 0`, а место слоя на холсте записано в пивоте спрайта. Если слои после сборки
  съезжают относительно друг друга, первым делом проверьте эту настройку импорта.
* **Группы Aseprite** превращаются в такую же иерархию объектов под корнем локации.
* **Слой разметки** (коллизия, границы камеры, зоны) рисуется любым цветом: учитывается только
  непрозрачность пикселя (порог `alphaThreshold` в конфиге), в игре такой слой не рисуется.
* **Имена слоёв** задают роль через правила конфига. Конфиг по умолчанию:

| Маска имени | Роль | Результат |
| --- | --- | --- |
| `bg_*`, `art_*` | Только спрайт | спрайт слоя, без коллайдеров |
| `col_*` | Статичная коллизия | `BoxCollider2D`-прямоугольники, слой физики `Floor`, тег `Floor` |
| `wall_*` | Статичная коллизия | то же, слой `Walls`, тег `Wall` |
| `plat_*` | Односторонняя платформа | слитые прямоугольники + `PlatformEffector2D` |
| `cam_*` | Границы камеры | фигура для `CinemachineConfiner2D` |
| `dead_*` | Килл-зона | триггер + `DeadZone` |
| `skip_*` | Пропустить | слой не попадает в сцену |
| всё остальное | Только спрайт | `defaultAction` конфига |

Маска работает с `*` и `?` без учёта регистра. Правила проверяются по порядку, срабатывает первое совпавшее.

## Окно «Построение локации»

### Превью сцены (верх окна)

Превью показывает всю сцену так, как её рендерит URP 2D. Снимает его отдельная скрытая камера:
в сцену она не сохраняется, на игровую камеру не влияет. Поверх картинки рисуются коллайдеры
локации (зелёным), выделенный объект (синим), слой, выбранный в таблице (оранжевым), и объект
под курсором (белым, с подписью).

| Действие | Что делает |
| --- | --- |
| клик | выделить объект в сцене (если это объект слоя, в таблице выберется его слой) |
| двойной клик | выделить и показать в Scene View |
| колесо мыши | зум к точке под курсором (×0.25 … ×64) |
| ПКМ / СКМ / Alt+ЛКМ + тянуть | сдвиг вида |
| «Сцена целиком» / «Локация» | в кадре вся сцена или только собранная локация |
| «Коллайдеры» | показать или скрыть коллайдеры локации |
| «Вписать» | сбросить зум и сдвиг |
| «Обновить» | перерисовать превью принудительно |

Картинка перерисовывается сама после правок сцены, Undo и смены иерархии.

### Разделы ниже

| Раздел | Что там |
| --- | --- |
| Локация в сцене | выбор собранной локации, если их в сцене несколько |
| Источник | `.aseprite`, конфиг правил, конфайнер камеры (находится в сцене сам) |
| Кнопки | **Построить/Перестроить**, **Очистить** (удаляет детей корня) |
| Масштаб карты | `worldScale` конфига, поле и кнопки − / + (шаг 0.5) |
| Путь камеры | выбрать, создать, править в сцене, построить коридор |
| Размер локации | размер в юнитах после масштаба: быстрая проверка против роста персонажа |
| Слои | таблица: слой → правило → что будет; клик по строке открывает карточку слоя |
| Карточка слоя | превью, группа, порядок, роль, поля роли, «Выделить в сцене», «Вернуть правилу конфига» |

**Масштаб карты** применяется сразу к собранной локации: арт и коллайдеры лежат под корнем
и растягиваются вместе с ним, перестраивать не нужно. С галочкой «Масштабировать путь камеры
вместе с картой» точки пути растягиваются от того же центра, а коридор перестраивается.
Масштаб хранится в **конфиге**, поэтому он общий для всех локаций с этим конфигом. Если уровням
нужен разный масштаб, заведите каждому свой конфиг.

## Роли слоёв

Роль берётся из двух мест, ручная сильнее:

1. **Ручное назначение**: в карточке слоя выбрать «Роль». Хранится в маркере локации, то есть в самой
   сцене, у всей команды одинаково. Имя такого слоя в таблице голубое, правило — «вручную».
2. **Правило конфига** по маске имени.

Общие поля всех ролей: `renderSprite` (рисовать спрайт слоя), `sortingLayer`, `sortingOrderOffset`
(сдвиг относительно порядка слоя в Aseprite), `zOffset`.

| Роль (`[AddTypeMenu]`) | Класс | Поля |
| --- | --- | --- |
| Локация/Только спрайт | `DecorationAction` | только общие |
| Локация/Статичная коллизия | `SolidColliderAction` | `shape`, `physicsLayer`, `tag`, `physicsMaterial` |
| Локация/Односторонняя платформа | `OneWayPlatformAction` | `physicsLayer`, `tag`, `surfaceArc`, `rotationalOffset`, `physicsMaterial` |
| Локация/Границы камеры | `CameraBoundsAction` | `shape` (по умолчанию BoundingBox), `padding`, `physicsLayer` |
| Локация/Триггер-зона | `TriggerZoneAction` | `shape`, `physicsLayer`, `tag` |
| Локация/Килл-зона | `DeadZoneAction` | как у триггер-зоны + компонент `DeadZone` |
| Локация/Пропустить | `IgnoreLayerAction` | слой не попадает в сцену |

Если в проекте нет слоя физики или тега, указанного в роли, объект остаётся на `Default` / `Untagged`,
а в окне появляется предупреждение.

### Форма коллайдера (`ColliderShapeMode`)

| Режим | Что строится | Когда |
| --- | --- | --- |
| **Boxes** | отдельные `BoxCollider2D` без `Rigidbody2D` | коллизия по умолчанию: каждый прямоугольник виден и правится руками |
| **Merged Boxes** | те же прямоугольники, слитые `CompositeCollider2D` | нужен ровно один коллайдер: платформы (эффектор), триггеры, границы камеры; гладкие стыки |
| **Outline** | `PolygonCollider2D` по контуру пикселей | склоны должны остаться наклонными |
| **BoundingBox** | один прямоугольник по габаритам слоя | границы камеры, большие зоны |

Прямоугольники режутся жадно: сначала горизонтальные полосы, потом полоса опускается вниз.
У отдельных боксов на стыках по верхней поверхности персонаж изредка может цепляться. Если на
каком-то слое это мешает, переключите его на Merged Boxes.

Платформы всегда строятся Merged Boxes (эффектору нужен один коллайдер). Границы камеры с режимом
Boxes тоже сливаются: конфайнеру нужна одна фигура.

### Если в файле нет слоя `cam_*`

Тогда границы камеры берутся из пути камеры, если его коридор подключён к конфайнеру. Без пути утилита
строит прямоугольник по габаритам всего уровня (`CameraBounds (по габаритам уровня)`).

## Конфиг `LocationBuildConfig`

`Create → Psynetika → Location Build Config`, лежит в `Assets/Resource/Level/`.

| Поле | Смысл |
| --- | --- |
| `worldScale` | масштаб корня локации (в Level 1 это 6: при PPU 100 около 16.7 пикселя арта на юнит) |
| `alphaThreshold` | с какой непрозрачности пиксель считается телом слоя |
| `simplifyTolerance` | сглаживание ступенек контура в режиме Outline, в пикселях (0 — точный контур) |
| `minPathPoints`, `minContourArea` | отсев мелких контуров (пыль, одиночные пиксели) |
| `minRectArea` | отсев мелких прямоугольников в режимах Boxes / Merged Boxes |
| `rules` | правила «маска имени → роль» |
| `defaultAction` | роль слоя, не подошедшего ни под одно правило |

## Путь камеры

Линия в сцене, по которой ходит камера. Вокруг линии строится **коридор**, и он становится
`BoundingShape2D` у `CinemachineConfiner2D`. Ширина коридора равна кадру камеры, поэтому камера
идёт ровно по линии, а не болтается в прямоугольнике всего уровня.

Объект пути живёт **вне** корня локации: «Перестроить» удаляет детей корня, а линия должна
пережить перестройку арта. Коридор — дочерний объект пути `Коридор (сгенерировано)`, он собирается
целиком заново: правьте линию, а не коллайдеры коридора.

### Управление в Scene View (пока путь выделен)

| Действие | Что делает |
| --- | --- |
| тянуть голубую точку | двигать линию |
| Shift + клик | добавить точку: в ближайший отрезок или продолжением за конец |
| Ctrl + клик (Cmd на Mac) | удалить точку под курсором (меньше двух точек удалить нельзя) |
| клик по значку посреди отрезка | кружок — гибкий отрезок, квадрат — прямой |
| тянуть оранжевые квадраты над и под точкой | запас: насколько камере можно подняться выше или опуститься ниже линии |
| тянуть фиолетовый квадрат в углу кадра точки | зум: наружу — отдалить, внутрь — приблизить |
| тянуть зелёную стрелку из центра кадра | фокус: вниз — камера ниже, вверх — выше |
| Ctrl + Z | отменить правку |

В левом нижнем углу Scene View есть панель с этим списком (сворачивается кнопкой «Скрыть клавиши»)
и переключатель **Новые отрезки: Гибкая / Прямая**. Пока зажат Shift или Ctrl, у курсора написано,
что сделает клик. Ctrl + перетаскивание точки не привязывает её к сетке: Ctrl в этом инструменте
всегда означает удаление.

### Гибкие и прямые отрезки

* **Гибкий** отрезок изгибается сглаживанием (`smoothing`) в кривую через точки.
* **Прямой** остаётся ровной линией при любом сглаживании. Гибкий отрезок рядом с прямым выходит
  точно по его направлению, без излома.
* Режим хранится в начальной точке отрезка (`straight`). Переключается значком в сцене, в инспекторе
  (раздел «Отрезки») и кнопками «Все отрезки гибкие / прямые».
* Shift + клик создаёт отрезок в режиме «Новые отрезки». Если точка разбила существующий отрезок,
  обе его половины получают этот режим.
* Разница заметна только там, где линия поворачивает: гибкий отрезок проходит точно через свои точки.
  При `smoothing = 0` или меньше трёх точках все отрезки прямые.

### Зум на участке пути

* У каждой точки есть `zoom`: 1 — обычный обзор камеры, 1.5 — видно в полтора раза больше
  (отдаление), 0.7 — ближе. Диапазон ручки ×0.2 … ×5, шаг 0.05.
* Между точками зум меняется плавно. **Участок с зумом** — это точки с одинаковым зумом на его концах:
  точки 3 и 4 с зумом 1.5, соседние с 1 → камера плавно отдалится к точке 3, пройдёт до 4 отдалённой
  и плавно вернётся.
* Где зум не 1, в сцене пунктиром показан кадр камеры и подпись «зум ×N».
* **Коридор расширяется вместе с зумом**: иначе отдалённый кадр не поместился бы, и конфайнер вытолкнул
  бы камеру с линии. После правки зума коридор нужно перестроить (или держать «Перестраивать сразу»).
* **Oversize Window у конфайнера обязателен.** Без него там, где коридор уже текущего кадра,
  конфайнеру некуда поставить камеру: на выходе из отдалённого участка камера застревает и зум
  не возвращается. Путь включает Oversize Window сам — при сборке коридора и при старте игры;
  `MaxWindowSize` ставится по самому большому зуму на пути. Если он выключен, инспектор пути
  предупредит и предложит кнопку.
* **В игре** путь сам меняет `OrthographicSize` камеры конфайнера по ближайшему к **цели камеры**
  (игроку, `Follow`) месту линии и зовёт `InvalidateLensCache()`. Цель, а не сама камера: камеру держит
  конфайнер, чья область зависит от зума, и зум по камере мог застрять вместе с ней. Работает, только если конфайнер стоит на `CinemachineCamera`,
  иначе инспектор предупредит. При выключении пути камера возвращается к исходному обзору.
* `zoomDamping` — плавность смены зума, сек. При 0 зум следует линии точно. С задержкой при
  приближении кадр может ненадолго оказаться шире коридора, и конфайнер его подвинет.

### Фокус на участке пути

* У каждой точки есть `focus`: сдвиг камеры относительно игрока в юнитах. `(0, -2)` — камера на 2 юнита
  ниже обычного, игрок выше в кадре. Между точками фокус меняется плавно, как зум.
* **В Scene View** у каждой точки пути есть зелёная стрелка вниз из центра кадра (центр — где будет камера,
  если игрок стоит в этой точке; считается по `TargetOffset`, `ScreenPosition` композера и зуму).
  Тяните стрелку вниз — камера ниже, вверх — выше (шаг 0.05). Горизонтальный фокус — полем `focus`
  в инспекторе. Где зум или фокус заданы, пунктиром показан весь кадр.
* Базовый сдвиг камеры задан в `Cameras.prefab`: `TargetOffset.y = -5` (камера на 5 юнитов ниже игрока),
  `ScreenPosition = 0`. Он действует везде, фокус участка прибавляется к нему. При зуме базовый сдвиг
  масштабируется вместе с обзором, фокус — нет.
* В игре фокус прибавляется к `TargetOffset` у `CinemachinePositionComposer`, плавность — тот же `zoomDamping`.
* **Коридор фокус не расширяет.** Если после сдвига камера не опускается (или не поднимается) до
  зелёной точки, её держит конфайнер: увеличьте у этой точки запас `down` (или `up`).
* Сброс — «Сбросить фокус у всех точек» в инспекторе пути.

### Поля `CameraPath`

| Поле | Смысл |
| --- | --- |
| `nodes` | точки: `position` (локальные координаты), `up`, `down`, `straight`, `zoom`, `focus` |
| `closed` | замкнуть путь: последняя точка соединяется с первой |
| `smoothing` | промежуточных точек кривой на отрезок: 0 — ломаная, 4–8 — плавно |
| `widthFromCamera` | ширина коридора из обзора виртуальной камеры конфайнера |
| `slack` | запас сверх обзора, юниты: насколько камере можно отходить от линии |
| `width` | ширина коридора вручную, когда обзор камеры не используется |
| `confiner` | конфайнер, которому отдаётся коридор |
| `physicsLayer` | слой физики объекта коридора (коридор — триггер, в физику уровня не вмешивается) |
| `zoomDamping` | плавность зума и фокуса в игре |

В инспекторе также: «Перестраивать сразу» (настройка у каждого своя, хранится в EditorPrefs),
«Построить / Перестроить коридор», «Убрать коридор», «Найти конфайнер в сцене», сводка по зуму
и «Сбросить зум у всех точек».

## Шаблон уровня

Шаблон — копия рабочей сцены (Level 1), очищенная от контента конкретного уровня. Скрипт не
расставляет префабы заново, а копирует сцену целиком, потому что половина обвязки живёт в оверрайдах
инстансов (цель камеры, размер линзы, ссылки UI на игрока) и при расстановке заново потерялась бы.

* **Собрать шаблон**: открыть рабочую сцену → «Шаблон уровня» → проверить галочки у корневых объектов
  → **Сохранить как шаблон уровня**. Каркас (камеры, Cinemachine, UI, EventSystem, игрок, `DeadZone`)
  отмечен сам, контент (враги, NPC, диалоги, арт, коллайдеры) — нет. Рядом написана причина.
  Шаблон сохраняется в `Assets/Scenes/Templates/Level Template.unity` с пустым корнем локации.
* **Создать уровень**: имя → **Создать**. Шаблон копируется в `Assets/Scenes/`, сцена открывается,
  и сразу открывается «Построение локации».

## Где что хранится

| Что | Где | Общее для команды? |
| --- | --- | --- |
| источник, конфиг, ручные роли слоёв, ссылка на путь камеры | `LocationBuildMarker` на корне локации (сцена) | да |
| правила, пороги, масштаб карты | ассет `LocationBuildConfig` | да, для всех локаций с этим конфигом |
| линия, зум, режимы отрезков | компонент `CameraPath` (сцена) | да |
| «Перестраивать сразу», «Новые отрезки», свёрнутость подсказок | EditorPrefs | нет, у каждого свои |

## Как добавить новую роль слоя

Новая роль — это один класс, без правки сборщика и окна: он сам появится и в правилах конфига,
и в списке «Роль» карточки слоя.

```csharp
using System;
using UnityEngine;

// Лестница: триггер, по которому игрок может карабкаться. Ladder — ваш компонент поведения.
[Serializable]
[AddTypeMenu("Локация/Лестница")]
public class LadderAction : LocationLayerAction
{
    [PhysicsLayerName] public string physicsLayer = "Default";

    public override string Describe() => "лестница";

    public override void Apply(LocationLayerSource layer, LocationBuildContext ctx)
    {
        GameObject target = CreateObject(layer, ctx);

        // Пустой список — коллайдер не построен, предупреждение уже в отчёте.
        if (BuildCollider(target, layer, ctx, ColliderShapeMode.MergedBoxes, true, 0f).Count == 0)
        {
            return;
        }

        target.layer = ctx.ResolveLayer(physicsLayer, layer.Name);
        target.AddComponent<Ladder>();
        ctx.Note("Ladder");
    }
}
```

* Объекты создавайте только через `CreateObject` / `ctx.CreateObject`: через них редактор регистрирует
  созданное в Undo.
* `ctx.Note(...)` дописывает текст в колонку «Что будет» таблицы, `ctx.Warn(...)` — предупреждение в окне.
* Поля роли переименовывать нельзя: конфиги и сцены хранят их по имени (см. `CLAUDE.md`).

## Частые проблемы

| Симптом | Причина / что делать |
| --- | --- |
| «Это не .aseprite-ассет» | в поле положен префаб или спрайт, а нужен сам файл `.aseprite` |
| «Merge Frame: все слои сплющены» | нажать «Переключить на Individual Layers» |
| слой жёлтый в таблице | ни одно правило не подошло: переименовать слой или назначить роль вручную |
| «фигура оказалась мельче порогов» | уменьшить `minRectArea` / `minContourArea` в конфиге |
| слои съехали относительно друг друга | проверить Pivot Space = Canvas в импорте `.aseprite` |
| персонаж цепляется на ровном полу | стык отдельных боксов: переключить слой на Merged Boxes |
| камера показывает пустоту за краем | нет `cam_*`, пути и конфайнера: подключить конфайнер или построить коридор |
| камера не опускается в «галочку» пути (острый поворот вниз) | коридор собран до исправления узлов — перестроить коридор; нужно ещё ниже линии — оранжевый нижний квадрат (`down`) у точки |
| зум в игре не меняется | конфайнер не на `CinemachineCamera`, или у всех точек зум 1 |
| после участка с зумом камера застряла, зум не возвращается | у конфайнера выключен Oversize Window: «Включить Oversize Window» в инспекторе пути или перестроить коридор |
| камеру дёргает при смене зума | коридор не перестроен после правки зума; поставить `zoomDamping` 0.2–0.4 и `Damping` конфайнера 0.2–0.5 |
| камеру дёргает всегда, даже без зума | `slack = 0`: коридор ровно в кадр, область камеры вырождается в линию нулевой толщины — поставить `slack` 0.5–1; у игрока `Rigidbody2D.Interpolate = Extrapolate` — переключить на `Interpolate` |
| изменения не видны после правки линии | «Перестраивать сразу» выключено или коридор ещё ни разу не строился: нажать «Построить коридор» |
