# Построение локации из .aseprite

Утилита собирает уровень из **одного файла Aseprite со слоями**: раскладывает слои по объектам сцены,
строит под них коллайдеры и подключает границы к камере Cinemachine. Коллизию больше не нужно
обводить руками — она берётся из того же файла, что и арт.

## Быстрый старт

1. В Aseprite разложить уровень по слоям и назвать их по конвенции: `bg_sky`, `art_level`,
   `col_ground`, `plat_wood`, `cam_bounds`, `dead_pit`.
2. В Unity: **Psynetika → Построение локации**.
3. Перетащить `.aseprite` в поле **Файл .aseprite**.
4. Если окно ругается на режим импорта — нажать **Переключить на Individual Layers**.
5. Нет конфига — нажать **Создать конфиг по умолчанию** (ляжет в `Assets/Resource/Level/`).
6. Посмотреть таблицу слоёв: у каждого слоя должно быть своё правило. Слой, которому правило
   не нашлось, подсвечен — почти всегда это опечатка в имени слоя. Слою без правила (или с
   неподходящим) роль назначается прямо в окне, см. «Роль слоя вручную».
7. **Построить локацию**.

Всё созданное лежит под объектом `Локация (сгенерировано)` с компонентом `LocationBuildMarker`.
Кнопки **Перестроить** и **Очистить** работают только с этим корнем — ручные объекты сцены
не трогаются никогда. Обе операции ходят через `Undo`, так что Ctrl+Z возвращает всё как было.

Источник, конфиг, ручные роли слоёв и ссылка на путь камеры хранятся в маркере, то есть в самой
сцене: у всех, кто её откроет, окно подтянет одинаковые настройки.

## Роль слоя вручную

Правила по маске имени хороши, пока художник держит конвенцию. Когда не держит — переименовывать
слои задним числом дороже, чем один раз отметить роль в окне.

Выберите слой в таблице: ниже откроется карточка — превью слоя, его группа, порядок и выпадающий
список **Роль**. В списке «Авто (правило конфига)» и все действия (`Статичная коллизия`,
`Односторонняя платформа`, `Границы камеры`, `Килл-зона`, `Триггер-зона`, `Только спрайт`,
`Пропустить`). Выбрали действие — тут же видны его поля: форма коллайдера, **слой физики** и **тег**,
которые получит объект. Тег и слой выбираются из списков проекта, вписать опечатку нельзя.

Земля — это `Статичная коллизия` с формой `Outline`, слоем `Floor` и тегом `Floor`
(значения по умолчанию, ничего доправлять не надо).

Ручное назначение **сильнее любого правила** конфига: правило по маске не должно перебивать
явный выбор человека. В таблице такой слой подписан правилом `вручную` и подсвечен голубым.
Кнопка **Вернуть правилу конфига** снимает назначение, **Выделить в сцене** показывает объект,
который получился из слоя в прошлой сборке.

Назначения живут в маркере локации. Если слой исчез из `.aseprite`, окно скажет об этом и
предложит убрать повисшие назначения.

## Путь камеры

Прямоугольные границы годятся, пока уровень — один экран. На длинном уровне с перепадами
прямоугольник пускает камеру в пустоту над крышами и под полом. Вместо него можно провести линию,
по которой камера должна ходить, и утилита построит вдоль неё коридор-конфайнер.

1. В окне сборки: **Путь камеры → Создать путь камеры**. В сцене появится объект `Путь камеры`
   с компонентом `CameraPath` и линией из двух точек по центру вида.
2. Правка линии прямо в Scene View, пока объект выделен:
   * перетаскивание точки — обычная ручка;
   * **Shift + клик** — добавить точку (в ближайший отрезок либо продолжением за конец);
   * **Ctrl + клик** — удалить точку под курсором;
   * **оранжевые квадратики** над и под точкой — запас: тянете верхний вверх, и в этом месте
     камера может подняться выше линии (высокий зал, уступ), между точками запас меняется плавно.

   Линия не обязана быть прямой: точки ставятся на любой высоте, а **Сглаживание** (по умолчанию 6)
   проводит через них плавную кривую вместо ломаной. 0 — прямые отрезки.
3. **Построить коридор** — по линии собирается фигура и подставляется в `CinemachineConfiner2D`.

Ширина коридора по умолчанию берётся из обзора камеры: поперёк горизонтального участка — высота
кадра (`Lens.OrthographicSize * 2`), поперёк вертикального — его ширина, на диагонали — проекция
кадра. Такой коридор держит камеру ровно на линии на любом участке. Поле **Запас** добавляет свободы по вертикали, галку
**Брать ширину из обзора камеры** можно снять и задать ширину руками.

Коридор — дочерний объект `Коридор (сгенерировано)`: статичный `Rigidbody2D` + `CompositeCollider2D`
из повёрнутых боксов (отрезок) и квадратов (узел). Объединение делает сам Unity, поэтому фигура
переживает и острые углы, и самопересечения пути. Править коллайдеры внутри бессмысленно —
следующая сборка соберёт их заново из линии.

Объект пути живёт **вне** корня `Локация (сгенерировано)`: перестройка арта чистит корень целиком,
а линия дизайнера должна её пережить. Если коридор построен, прямоугольник по габаритам уровня
утилита уже не строит и пишет об этом в отчёт.

## Конвенция имён слоёв

Это **данные, а не код** — таблица лежит в `LocationBuildConfig` и правится под любой другой стиль
именования. Набор по умолчанию:

| Маска слоя | Что получится |
| --- | --- |
| `bg_*`, `art_*` | только спрайт: sorting layer, порядок, сдвиг по Z |
| `col_*` | `PolygonCollider2D` по контуру, слой `Floor`, тег `Floor` |
| `wall_*` | `PolygonCollider2D` по контуру, слой `Walls`, тег `Wall` |
| `plat_*` | прямоугольники + `CompositeCollider2D` + `PlatformEffector2D`, слой `Platform` |
| `cam_*` | коллайдер-триггер → `CinemachineConfiner2D` |
| `dead_*` | триггер + скрипт `DeadZone` |
| `skip_*` | слой не попадает в сцену |
| остальное | только спрайт |

Порядок правил значим: берётся **первое** совпавшее. Маска понимает `*` и `?`, регистр не важен.

Слои-разметки (`col_`, `plat_`, `cam_`, `dead_`) по умолчанию не рисуются — за это отвечает галка
**Рисовать спрайт слоя** у действия. Группы Aseprite превращаются во вложенные объекты сцены.

Если слоя `cam_*` в файле нет, границы камеры всё равно строятся — прямоугольником по габаритам
всех слоёв, с предупреждением в отчёте. Исключение — построенный путь камеры: он сильнее,
см. «Путь камеры».

## Масштаб: почему локация кажется мелкой

Арт уровня в `Level 1` стоит **с масштабом 6**. При PPU 100 это ~16.7 пикселя арта на юнит:
холст 3771x890 px превращается в 226x53 юнита, а персонаж ростом 2.08 юнита занимает ~35 пикселей.
Если строить в масштабе 1, локация выходит ровно в 6 раз мельче персонажа.

За это отвечает **`worldScale`** в конфиге (по умолчанию `6`) — множитель на корне локации.
Масштабируется именно корень, а не координаты: спрайт рисуется по своему PPU, поэтому растянуть
арт и коллайдеры можно только вместе.

Окно после разбора показывает итог — `Размер локации: 226.3 x 53.4 юнитов (масштаб 6)`.
Сравните с ростом персонажа (~2.1 юнита): это самая быстрая проверка, что масштаб сошёлся.

## Шаблон уровня

Готовый шаблон уже лежит в проекте: `Assets/Scenes/Templates/Level Template.unity`.

Это обычная сцена, и новый уровень делается её копией — `Ctrl+D` в Project или кнопка
**Создать** в окне утилиты. Обёртки `.scenetemplate` намеренно нет: Unity при создании сцены из
шаблона обходит все зависимости и в этом проекте (263 `.aseprite`, каждый с пачкой саб-ассетов)
заваливает консоль `PPtr cast failed`, а часть ассетов по умолчанию ещё и клонирует —
каждый уровень получал бы свои копии `CharacterDatabase`, способностей и `ShopList`.
Копирование файла всё это обходит стороной.

Шаблон снят с `Level 1` и содержит шесть корней: `Cameras`, `Player`, `SatanHPBar` (UI), `EventSystem`,
`Shop`, `DeadZone` — плюс пустой корень `Локация (сгенерировано)` с маркером под сборку.
Весь контент уровня (арт, 5 врагов, 4 NPC со спавнерами, платформы, лестница, сундук, монета,
триггеры диалога и панели, `ColliderCamera`) вырезан: из 146 блоков сцены осталось 62.

`BoundingShape2D` конфайнера в шаблоне пустой — границы подставит первая же сборка локации.
Всё остальное на месте: `TrackingTarget` камеры смотрит на игрока, `Lens.OrthographicSize 6`,
`CameraDistance 10`, `UIScript.gameplayUI` и `FinishPanel`, `Shop.player`/`Shop.inventory`,
база персонажей диалогов.

### Пересобрать шаблон

Когда каркас изменится, шаблон снимается заново утилитой **Psynetika → Шаблон уровня**.

Шаблон это обычная сцена, снятая копией с рабочей и очищенная от контента конкретного уровня.
Именно копия, а не скрипт, который заново расставляет префабы: в `Level 1` половина рабочей обвязки
живёт **в оверрайдах инстансов**, а не в самих префабах —

* `Cameras` переопределяет `TrackingTarget` на игрока, `Lens.OrthographicSize`, дистанцию,
  lookahead и мёртвую зону композера;
* `UI` переопределяет `gameplayUI`, `FinishPanel`, `Shop.player` и `Shop.inventory`,
  аватары диалогов, привязки `OnClick` и всю раскладку.

Расстановкой префабов заново это не воспроизвести, копированием сцены — сохраняется целиком.

**Снять шаблон:** открыть рабочую сцену (`Level 1`), в окне посмотреть список корневых объектов.
Утилита сама помечает каркас (камера, игрок, UI, ввод, килл-зона) и снимает галки с контента
(арт, враги, NPC, триггеры, собираемое) — у каждой строки написано, почему она попала в свою группу.
Кнопка **Сохранить как шаблон уровня** кладёт результат в `Assets/Scenes/Templates/Level Template.unity`
и возвращает вас в исходную сцену; она не меняется.

**Новый уровень:** имя + кнопка **Создать** — шаблон копируется в `Assets/Scenes/<имя>.unity`,
открывается, и сразу поднимается окно сборки локации. Руками то же самое: `Ctrl+D` на шаблоне
в Project и переименовать.

## Формы коллайдеров

Форма выбирается у каждого правила отдельно:

| Режим | Что делает | Когда брать |
| --- | --- | --- |
| **Outline** | контур по границе пикселей, `PolygonCollider2D` с путём на каждый кусок | земля и стены, особенно со склонами |
| **Boxes** | разбиение на прямоугольники, `Rigidbody2D` (Static) + `CompositeCollider2D` + `BoxCollider2D` | платформы, триггер-зоны, прямая геометрия |
| **BoundingBox** | один прямоугольник по габаритам | границы камеры |

Дырки в геометрии поддерживаются: замкнутый контур внутри другого вычитается из фигуры.

Пороги резки — в конфиге:

| Параметр | Смысл |
| --- | --- |
| `alphaThreshold` | с какой непрозрачности пиксель считается телом слоя |
| `simplifyTolerance` | сглаживание ступенек пиксель-арта, в пикселях. `0` — точный контур, `1.5–3` — гладко и дёшево |
| `minContourArea` | контуры мельче этой площади выбрасываются (пыль, одиночные пиксели) |
| `minRectArea` | то же для режима `Boxes` |

## Из чего собрана утилита

```
LocationBuilderWindow      окно сборки локации, Undo, диагностика импорта  (Editor/)
LevelTemplateWindow        окно шаблона уровня: снять шаблон, создать уровень  (Editor/)
AsepriteImportFixer        переключение layerImportMode, конфиг по умолчанию  (Editor/)
LocationBuildRunner        разбор слоёв и прогон правил, отчёт
LocationBuildConfig        SO: пороги + таблица правил
LocationLayerRule          маска имени слоя + действие
LocationLayerAction        что сделать со слоем  (Actions/)
LocationColliderFactory    сборка коллайдера по маске
LocationBuildContext       состояние одной сборки: корень, кеши, отчёт
LocationBuildMarker        метка корня: источник, конфиг, ручные роли слоёв, путь камеры
LocationLayerOverride      ручное назначение роли слою, сильнее правил конфига
NameDropdownAttributes     [TagName], [PhysicsLayerName], [SortingLayerName] для строковых полей
NameDropdownDrawers        выпадающие списки тегов и слоёв проекта  (Editor/)
Geometry/                  SpriteMask2D, ContourTracer, PathSimplifier, RectDecomposer
```

Путь камеры лежит рядом, в `Assets/Scripts/Level/CameraPath/`:

```
CameraPath                 линия в сцене: точки, сглаживание, ширина коридора, конфайнер
CameraPathPoint            точка пути: положение + запас вверх/вниз
CameraCorridorFactory      коридор вдоль пути: полигоны отрезков и узлов + CompositeCollider2D
CameraPathEditor           ручки в Scene View, горячие клавиши, кнопки сборки  (Editor/)
```

`Editor/` знает про редактор, всё остальное — чистый `UnityEngine` и работает и в рантайме,
если однажды понадобится строить локацию на лету.

## Новый вид разметки

Тот же приём, что у `EnemyAttackModule` и `AbilityNode`: **новый класс-действие, без правки билдера.**

```csharp
[Serializable]
[AddTypeMenu("Локация/Лестница")]
public class LadderAction : LocationLayerAction
{
    public override string Describe() => "лестница";

    public override void Apply(LocationLayerSource layer, LocationBuildContext ctx)
    {
        GameObject target = CreateObject(layer, ctx);
        Collider2D collider = BuildCollider(target, layer, ctx, ColliderShapeMode.Boxes, true, 0f);

        if (collider == null)
        {
            return;
        }

        target.layer = ctx.ResolveLayer("Platform", layer.Name);
    }
}
```

Класс сразу появится в выпадающем списке правил конфига — дальше это настройка данных.
Для зоны с поведением можно унаследоваться от `TriggerZoneAction` и переопределить `Configure()`,
как сделано в `DeadZoneAction`.

## Чего утилита не делает

* Не правит существующую ручную коллизию. Старые `PolygonCollider2D` в `Level 1.unity` удаляются
  руками — и только после того, как сгенерированные признаны годными.
* Не собирает уровень из нескольких файлов: источник один, компоненты художник вклеивает в Aseprite.
* Не трогает `.meta` файлов руками — режим импорта переключается через API импортёра.

## Осторожно с переключением импорта

`Готовый уровень.aseprite` сейчас импортируется как **Merge Frame** (один сплющенный слой), и из него
сделан `Assets/Prefabs/Готовый уровень.prefab`, инстанс которого стоит в `Level 1.unity`.
Переключение на **Individual Layers** перегенерирует model prefab, и у этой обёртки могут слететь
оверрайды. Обкатывайте на копии файла или в `Assets/Scenes/test level.unity`.
